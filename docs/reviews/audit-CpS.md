## 结论速览

**总判定：核心语义完全符合定义（1050/1050 差分零差异），但有一个会让宿主挂死的死循环缺陷。**

- 三个文件里这是**最干净的一个**：父项（左侧最右小于末项者）→ 沿父链从右往左找第一个与末项互素者作为坏根 → `L = m−1−k`、`delta = 末项 − 坏根 − 1`、复制 `a[j] = delta + a[j−L]`，与 LPrSS 的 `expandArr` **逐条同构**。按定义独立实现的参考器在 1050 次比较中**零差异**，手工实例（`1,3,5,7`、`1,2,4,8`、`1,6,10,15` 等）全部吻合。
- 源码注释里那句「`coprime()` 返回值语义与名字相反：返回 1 表示有 >1 公因子」确实如此，但**逻辑是对的**：`while (hasCommonFactor(末项, g(k)) === 1) k = fb[k]` 就是「不互素则继续往左，停在第一个互素者」，与定义一致。
- **但 `fb[0] = 0`（不是 −1）+ 没有输入校验，构成死循环**：当链走到 `k=0` 且第 0 项与末项不互素时，`k = fb[0] = 0` 永远不变，函数不返回。实测 `0,2,4`、`2,4,8`、`0,2`、`0,2,6` 的 `fs(1)` / `fs(2)` 全部 2.5 秒超时无返回。合法式以 1 开头时 `gcd(末项,1)=1` 保证循环终止，所以只在非标准输入触发——但插件不校验输入，宿主传错即挂死，这是**本轮三个记号里最该优先修的缺陷**。
- 另有：`hasCommonFactor` 对 `a=0` 的语义错误（数学上 `gcd(0,b)=|b|`，只有 `|b|=1` 时互素，源码判「不互素」）；含 0 序列被 0 哨兵截断；`1,-1,2` 产生负数；`fsLimit(0)="1,1"` 越界；零/后继 `fs` 未短路。
- **好消息**：`bias=0`，解析步进正确（不受 PPS 家族 9/99 缺陷影响）；`typeOf("0")=1`、`pred("0")="0"` 正确；`less` 序性质全 0 违反；纯函数性通过；不会产生 RCS 那种零输入负数（`"0"` 的 `fs(1)="0"`）。

| # | 定义条款 | 判定 | 说明 |
|---|---|---|---|
| 1 | 极限表达式 `1,ω` | ⚠️ | `fsLimit(a)="1,"+(a+1)` 相容（a≥1），`fsLimit(0)="1,1"` 后继、越界 |
| 2 | 坏根 = 末项祖先项中**最靠右**与末项互素者 | ✅ | 从直接父起沿 `fb` 链向左，第一个 `gcd=1` 即停；1050/1050 一致 |
| 3 | 展开为 LPrSS 展开 | ✅ | `delta = hi−lo−1`、`L = x−1−k`、逐项 `+delta`、截断 `l*n+x−1`，与 `lprss.ts expandArr` 完全一致 |
| 4 | 「祖先项」是否含末项自己 | ❔ 定义歧义 | 源码不含自己（从父开始）；若含自己且末项=1 会导致 L=0 |
| 5 | ONP2：结果为 0 返回 `"0"` | ✅ | `pred("0")="0"`、`typeOf("0")=1` |
| 6 | `less` 序数比较 | ❔ 定义未覆盖 | 字典序，序性质完好 |

## 1. 定义与实现的映射

| 定义概念 | 代码位置 | 实现方式 |
|---|---|---|
| 父项 | `coprime.ts:41-48` | `fb[i]` = 最右 `j<i` 使 `g(j)<g(i)`；`g(i)===1 → fb[i]=-1`；`fb[0]=0` |
| 互素判定 | `:11-19` | `hasCommonFactor(a,b)`：从 `c=2` 试到 `aa+1`，若 `aa%c===0 && bb%c===0` 返回 **1**（不互素），否则 0 |
| 坏根（最靠右互素祖先） | `:33-35` | `let k=fb[末项]; while (hasCommonFactor(末项, g(k))===1) k = fb[k] ?? 0;` |
| `L` | `:35` | `this.l = this.x - 1 - k` |
| `delta` | `:36-38` | `hi − lo − 1`，其中 `hi=末项`、`lo=g(k)` |
| 复制 / `[n]` 截断 | `:38` | `for j=x-1 .. l*n+x-2: a[j] = delta + a[j-l]`；总长 `m + L·n − 1` |
| 极限基本列 | `:24-26` | `seqLimitTwo(a)` → `"1,"+(a+1)` |
| 类型 / 前驱 / 比较 | `core/notation.ts` | `seqType0` / 去末项 / `seqCompare` |

**与 LPrSS 的等价性**（前一轮已验证的 `expandArr`）：

```
LPrSS : delta = last − b[i] − 1 ; L = m − i − 1 ; r[j] = r[j−L] + delta (j 从 m−1 起)
CpS   : delta = hi   − lo   − 1 ; l = x − 1 − k ; a[j] = delta + a[j−l] (j 从 x−1 起)
```

两者只在「父项如何选」上不同：LPrSS 取左侧最右小于末项者，CpS 取该父链上最靠右的互素者。这正是定义所要求的替换。

## 2. 逐条审查

### 2.1 差分：1050/1050 零差异（✅）

按定义独立实现参考器（父项 → 祖先链 → 最右 `gcd=1` → LPrSS 展开），对 15 个手工样本 + 160 个随机样本（1 开头、值 1..15、末项 ≥2）× `n=0..5` 比较：

```
一致=1050  不一致=0  跳过(无互素祖先)=0
```

`n=0` 分支（删末项）也一致。手工实例的坏根定位：

| 输入 | 末项 | 祖先链值 | 最右互素者 | `fs(1)` |
|---|---|---|---|---|
| `1,4,6` | 6 | [4,1] | 1（4 与 6 不互素） | `1,4,5,8` |
| `1,2,4,8` | 8 | [4,2,1] | 1 | `1,2,4,7,8,10` |
| `1,3,5,7` | 7 | [5,3,1] | **5**（与 7 互素） | `1,3,5,6` |
| `1,6,10,15` | 15 | [10,6,1] | 1 | `1,6,10,14,19,23` |
| `1,1,2` | 2 | [1] | 1 | `1,1,1` |

「最靠右」的语义也验证过：`1,3,5,7` 停在第 3 项（值 5），不再继续往左找 3 或 1 ✓。

### 2.2 死循环：非标准输入让 `fs` 永不返回（❌ 高）

```
coprime.ts:30   fb[0] = 0;                       // 不是 -1
coprime.ts:34   while (hasCommonFactor(末项, g(k)) === 1) k = fb[k] ?? 0;
```

当父链走到 `k=0`、且 `g(0)` 与末项不互素时，`k = fb[0] = 0` 恒定，循环条件恒真。合法式首项为 1 → `gcd(末项,1)=1` → 必停；但只要第 0 项不是 1（或第 0 项为 0），就会挂死。独立子进程 + 2.5s 超时实测：

```
"0,2,4"   fs(1)/fs(2) → ETIMEDOUT（无返回）
"2,4,8"   fs(1)/fs(2) → ETIMEDOUT
"0,2"     fs(1)/fs(2) → ETIMEDOUT
"0,2,6"   fs(1)/fs(2) → ETIMEDOUT
"1,0,2"   fs(1)="1"（0 被哨兵截断，未触发）
"1,6,10,15" fs(1)="1,6,10,14,19,23"（合法，正常）
```

> `2,4,8` 虽然不是「1 开头」的合法式，但宿主若从别的记号/文本导入表达式，插件没有任何校验就会挂死；对比 RCS 在同样输入上正常返回、LELS 在零/全零输入上也会挂死，这是三者共通的健壮性问题，但 CpS 的触发面最宽（首项 ≠1 即可）。

### 2.3 `hasCommonFactor` 的 gcd 边界（⚠️）

- `aa=0`：`0 % c === 0` 对任意 c 成立，若 `bb%c===0` 也成立（如 bb 偶数）就返回 1（不互素）。数学上 `gcd(0,b)=|b|`，只有当 `|b|=1` 时互素。源码把 `(0,2)` 判为不互素 ✓ 碰巧对，把 `(0,1)` 也判为不互素 ✗（应为互素）。
- 循环上限写成 `aa+1` 而不是 `min(|a|,|b|)`：对 `aa ≫ bb` 只是多试几次，结果不变；但 `aa=1` 时上限 2、`c=3` 退出，返回 0（互素）✓。
- `g(i)===1 → fb[i]=-1`，而 `fb[-1] ?? 0 = 0`、`g(-1)=0`：`hasCommonFactor(末项,0)` 会因 `0%c===0` 判不互素，于是 `k` 跳到 0，再靠 `g(0)=1` 停下。链条正确但绕了一圈，属于脆弱实现。

### 2.4 定义歧义：「祖先项」是否含末项自己（❔）

源码从 `fb[末项]`（直接父）开始，不含末项自己。若按某些体系（如 BMS 定义里「一个元素自己，以及它的父项…」）把「祖先项」理解为含自己，则末项=1 时 `gcd(1,1)=1` 会选自己为坏根、`L=0`，展开无意义。源码的读法更合理，但建议在文档中明确「祖先项 = 父、父的父……，不含自身」。

### 2.5 接口契约（⚠️）

| 检查 | 结果 |
|---|---|
| `fsLimit` | `a=0 → "1,1"`（type=2 后继，越界）；`a≥1 → "1,a+1"` ✓ |
| `typeOf("0")` / `pred("0")` | `1` / `"0"` ✓ |
| 零/后继的 `fs` | 未短路：`fs(1,"1")="1"`（输出不变）、`fs(1,"1,1")="1"`、`fs(1,"1,2,1")="1,2"` |
| 含 0 的合法式 | `1,0,2 → type=2, pred="0", fs(1)="1"`（0 被 0 哨兵截断） |
| 非法输入 | `abc`/`""` → `fs(1)="0"`；`1,-1,2` → `fs(1)="1,-2"`、`fs(2)="1,-2,-5"`（负数）；首项非 1 的 `2,3` → `fs(1)="2,2"` |
| 解析步进 | `bias=0`，`txar` 步进恒为「位数+1」，9/99/多位数均正确 ✓ |
| `less` | 字典序；13 样本反自反 0 / 双向 0 / 不可比 0 / 传递违反 0；`less(fs(n),fs(n+1))` 全真 |
| 纯函数性 | `fs` 两次一致 ✓、`less` 后 `fs` 一致 ✓、`fs` 后 `less` 一致 ✓ |
| 死循环 | ❌ 见 §2.2 |

## 4. 整改建议（按优先级）

1. **立刻修 C-D1**：给 `while` 加终止护栏（`if (k === fb[k]) break` 或 `fb[0]=-1`），并在 `fs` 入口校验合法式。回归用例固定为 `0,2,4`、`2,4,8`、`0,2,6` 的 `fs(1)/fs(2)`，要求 2 秒内返回。
2. **修 C-D2 / C-D4**：换成标准 `gcd`，去掉 `fb[-1]→0` 的绕行；解析层消除 0 哨兵歧义，杜绝负数输出。
3. **澄清 C-D3**，把「祖先项不含自身、首项恒为 1、元素为自然数」写进接口文档。
4. **统一索引与协议（C-D5、C-D6）**，与前几轮报告的建议一并处理。
