## 结论速览

**总判定：不能算「完全遵守」；主体是一套 exe 的矩阵差值表算法，与定义文字只能结构性对应。有三处可定量偏差、四类定义条款无法形式化验证。**

- **能对应上的**：每行视作一个「项」（源码注释称 Base-ω Array），`par1()` 沿行向上找第一个严格更小的行 ≈ 父项；`d[r][j] = m[r][j] − m[par1(r)][j]` ≈ 阶差；坏根沿父行链找「阶差小于末行阶差」者（**4/5 构造例一致**）；末行减 1 + 复制单元向右复制 `times=n` 次（`fs(n)` 行数实测随 n 线性增长：`(0,0)(1,1)(2,0)` 为 2→4→6→8→10→12 行）≈「重复 n 次得 [n] 展开式」。
- **三处可定量偏差**：
  1. **差值表左侧列抄原值**：源码从最右列往左算差值，遇到第一个非零差值即停，更左侧列直接 `dPut(r,j, at(r,j))`（抄原值），不是「项 − 父项」。构造 `(0,0)(1,1)(2,2)`（父行非零）：源码 `d[2][0]=2`，定义应为 `2−1=1`；`(0,0,0)(1,1,0)(2,2,0)` 同样。直接违反定义「一个项减去自己的父项得到的是阶差」。
  2. **`isUnit` 分支绕过坏根定义**：`(0,0)(1,1)(2,1)` 源码取直接父 `p=1`，按定义应为 `p=0`。
  3. **`typeOf` 与 `ex` 分支自相矛盾**：`(0,0)(0,1)` 末行首列 0，`typeOf="3"`（极限），`ex()` 却走 `if (at(x-1,0)===0)` 的「末项是 0」分支（`times=1`），输出 `(0)(1)/(0)(2)/(0)(3)…`，行数恒 2、末行随 n 变化；按定义「末项是 0 → 表达式是删末项的后继」不该有基本列。
- **一个高危工程缺陷**：`(0)`、`(0)(0)`、`(0,0)(0,0)`、`""`、`"abc"` 的 `fs(1)` **全部 2.5 秒超时无返回**——末行全 0（或内部 `y=0`）时 `while (at(x-1,c0)===0) c0++` / `while (dAt(x-1,c0)===0) c0++` 越界读恒为 0，无限递增。这些正是定义里「末项是 0」应由 `pred` 短路的路径。
- **四类定义条款无法逐条验证**（不是「已判定违反」，而是**审查边界**）：极限表达式 `0,(0,1,2)` 与 `fsLimit` 的对应；序数减法 `min{γ|β+γ=α}`；公差 `δ`/`δ[n]` 与「左加/右加 δ[n]」；**提升度**（逐个删掉与鉴定元相同的单元）与**鉴定元**（末项展开形成的复制单元、首尾衔接）。源码里没有这些名字，只有 `mul = dAt(r-pr,low)/(dAt(x-1-pr,low)+1)`、`cut`、`firstNZ/lastNZ`、`times` 等近似机制；注释自述是「复制差值表并按倍数 mul 累加，再把差值还原成元素值」。
- **好消息**：`less` 序性质（反自反/非对称/完全/传递）全 0 违反，注释里「修复 exe 不反对称」的样例 `(0,0,0)(0,0,1) vs (0)(1)` 现为 `false/true`（不再双向）；`fs(n)` 的 `less` 单调性全真；纯函数性通过。源码注释还明确记录了多处「按源 exe 实测」和「有意偏离 exe 的修复」，说明基准是**复原 exe**，不是按定义重写。

| # | 定义条款 | 判定 |
|---|---|---|
| 1 | 极限表达式 `0,(0,1,2)` | ❔ 无法对应（`fsLimit(a)` 为 `(0…)(0…1)` 两行矩阵，`a=0 → "(0)"` 后继） |
| 2 | 父项 = 左侧最右小于 A 的项 | ⚠️ 结构对应：源码是**行级**父项 `par1`（按列从右往左字典序比较），定义是**元素级** |
| 3 | 阶差 = 项 − 父项；0 的阶差仍为 0 | ❌ 部分：右侧列一致，**左侧列抄原值**（见上） |
| 4 | 序数减法 `α−β=min{γ\|β+γ=α}` | ❔ 源码为逐列数值相减，未见序数减法 |
| 5 | 坏根 = 祖先链中最右阶差 < 末项阶差者 | ⚠️ 4/5 构造例一致；`isUnit` 分支 1/5 不一致 |
| 6 | 末项是 0 → 后继 | ❌ 未短路，`fs` 死循环；`typeOf` 与 `ex` 分支矛盾 |
| 7 | 末项是后继序数 → δ 为前继、重复 n 次 | ❔ 见到 `times=n` 与末行减 1，但无显式 δ |
| 8 | 末项是极限序数 → `δ[n]` 标准基本列、提升度/鉴定元/左加右加 | ❔ **定义条款无法形式化，源码无对应实现** |
| 9 | ONP2：结果为 0 返回 `"0"` | ❌ `fs(0)` 与 `pred` 不一致、返回空串 |

## 2. 逐条审查

### 2.1 表示层：行 = 项（⚠️ 与定义的写法不同）

定义按「序列的项」叙述（父项是「指定项 A 左侧最右边小于 A 的项」），源码把**每一行**当作一个项、行内各列是 ω 进制数组的位。这是表示层差异，不算直接违反，但使「项 − 父项」「左加 δ[n]」等条款无法逐字对照。实测输出列数恒为内部 `y−1`：`(0,0)(0,1)`（输入 2 列，内部 y=3）展开后输出 1 列 `(0)(1)`，源码 `:181-184` 还有 `if (s2===1 && x===2 && 2<y) y--` 的列数收缩——定义未规定此规范化。

### 2.2 阶差：左侧抄原值（❌ 可定量）

独立复算「源码差值表」与「按定义逐列全算 `项 − 父项`」的差值表，逐格比较：

| 输入 | 父行 par1 | 源码 d（末行） | 定义 d（末行） | 差异 |
|---|---|---|---|---|
| `(0,0)(1,1)(2,2)` | [0,0,**1**] | `[2,1,0]` | `[1,1,0]` | **d[2][0]：2 vs 1** |
| `(0,0,0)(1,1,0)(2,2,0)` | [0,0,**1**] | `[2,1,0]` | `[1,1,0]` | **d[2][0]：2 vs 1** |
| `(0,0,0)(1,1,1)(2,2,0)` | [0,0,0] | `[2,2,0,0]` | `[2,2,0,0]` | 一致（父行全 0，抄原值恰好等于差值） |
| `(0,0)(1,1)(2,0)` | [0,0,0] | `[2,0,0]` | `[2,0,0]` | 一致 |
| `(0,0)(1,1)(2,1)` | [0,0,1] | `[1,0,0]` | `[1,0,0]` | 一致 |

偏差只在**父行非零且第一个非零差值列靠右**时暴露：源码在 break 列左侧直接抄 `at(r,j)`，而定义要求继续减父行对应列。对应 `fs(1)` 实测：`(0,0)(1,1)(2,2) → "(0,0)(1,1)(1,2)"`。

### 2.3 坏根：`isUnit` 分支（❌ 1/5 不一致）

按定义「祖先链中最右边阶差值小于末项阶差的项」复算（`compaD(末行, p) === 1`），与源码 `p` 对照：

| 输入 | 末行 d | isUnit | 源码 p | 定义 p | 一致 |
|---|---|---|---|---|---|
| `(0,0)(1,1)(2,2)` | [2,1,0] | false | 1 | 1 | ✓ |
| `(0,0,0)(1,1,0)(2,2,0)` | [2,1,0] | false | 1 | 1 | ✓ |
| `(0,0,0)(1,1,1)(2,2,0)` | [2,2,0,0] | false | 0 | 0 | ✓ |
| `(0,0)(1,1)(2,0)` | [2,0,0] | false | 0 | 0 | ✓ |
| `(0,0)(1,1)(2,1)` | [1,0,0] | **true** | **1** | **0** | ✗ |

`isUnit` 时源码直接用 `par1(x-1)`（直接父），跳过了定义的「沿链比较阶差」规则。这大概对应定义里「末项是后继序数」分支的简化，但定义把坏根规则写在展开之前，应通用——至少需文档澄清。

### 2.4 三分支展开（❌ / ❔）

- **「末项是 0 → 后继」**：`typeOf` 用 `matrixType0`（末行**全 0** → '2'），`ex` 用 `if (at(x-1,0)===0)`（末行**首列**为 0）判定。两者口径不同：`(0,0)(0,1)` 首列 0、但非全 0 → `typeOf="3"`（极限），`ex` 却走「末项是 0」分支（`times=1`），输出 `(0)(1)/(0)(2)/(0)(3)…`（行数恒 2）。同一表达式在协议层与展开层被当成两种类型。
- **「末项是后继序数 / 极限序数」**：源码没有显式类型分支，只有 `times = n`（首列非 0）或 `times = 1`（首列 0），以及末行 `−1`。定义里的「公差 δ = 末项减坏根的值的前继」「δ[n] 用 LELS 标准基本列」「提升度大于环根则右加 δ[n]、其他左加 δ[n]」在源码里**找不到对应变量**；`mul = dAt(r-pr,low)/(dAt(x-1-pr,low)+1)` 与 `cut` 分界左右累加，至多是功能近似，**无法判定合规**。
- **「提升度 / 鉴定元」**：定义要求「把序列的末项这个表达式展开，形成的复制单元」作为鉴定元，且「首尾衔接」（`0,1,1`/`1,0,1`/`1,1,0` 等价），提升度是「从右往左逐个删掉与鉴定元相同的单元，能删掉的最大数量」。源码无字符串/循环单元匹配逻辑，只有 `firstNZ / lastNZ / nz / cut` 的列扫描。**这是本报告最大的审查边界**：定义条款没有形式化到可写独立参考器的程度，不能说实现违反，也不能说实现符合。
- **「重复 n 次得 [n]」**：`for (;;) { if (times*pr + x < r) { x = times*pr + x − 1; return; } … r++ }` 生成 `times·pr` 个新行，与「复制单元向右复制 n 次」结构性对应。实测 `(0,0)(1,1)(2,0)`：n=0 2 行、n=1 4 行、n=2 6 行……n=5 12 行 ✓。

### 2.5 接口契约（❌ 高危 / ✅ 部分）

| 检查 | 结果 |
|---|---|
| **零/全零/非法输入的 `fs`** | `(0)`、`(0)(0)`、`(0,0)(0,0)`、`""`、`"abc"` 的 `fs(1)` **全部 ETIMEDOUT（2.5s 无返回）**。原因：末行全 0 或 `y=0` 时 `while (at(x-1,c0)===0) c0++` / `while (dAt(x-1,c0)===0) c0++` 越界读恒为 0 |
| `fsLimit` | `a=0 → "(0)"`（type=2 后继、越界）；`a=1..5 → "(0)(1)"`、`"(0,0)(0,1)"`、… 两行 a 列，第 2 行末列 1。与定义极限表达式 `0,(0,1,2)` 的对应**无法确认** |
| `fs(0)` vs `pred` | `fsLimit(0)="(0)"` 的 `pred="0"` 但 `fs(0)=""`；`""`/`"0"` 的 `pred=""`、`fs(0)=""`。**协议要求结果为 0 返回 `"0"`**，实现返回空串 |

| `less` | 序性质：反自反 0 / 双向 0 / 不可比 0 / 传递违反 0 ✓；注释中的修复点 `(0,0,0)(0,0,1) vs (0)(1)` 为 `false / true`（不再双向）✓ |
| `fs(n)` 单调性 | 5 个表达式 × n=1..5，`less(前, 后)` 全为 true ✓ |
| 纯函数性 | `fs` 两次一致 ✓、`less` 后 `fs` 一致 ✓、`fs` 后 `less` 一致 ✓；`fs(3,"(0,0)(1,1)(2,0)")` 输出稳定 |

## 4. 整改建议（按优先级）

1. **先修 L-D2 / L-D3 / L-D5**（不改定义即可修）：`fs` 入口按 `typeOf` 分流；`pred/fs(0)` 在零/单行时返回 `"0"`；统一「末项是 0」判定；给所有 `while (===0) c0++` 加上界。回归用例固定为 `(0)`、`(0)(0)`、`(0,0)(0,0)`、`""`、`"abc"` 的 `fs(1)`，要求 2 秒内返回。
