## 结论速览

**总判定：不完全遵守。**

- **数学展开规则是忠实的**：坏根（最右小于末项者）、好部 G、坏部 B、阶差 `d = s_n − s_k − 1`、`B_m = B + m·d` 全部与定义逐字对应；按 Wiki 公式独立实现的参考展开器做了 90 样本 × 6 = **540 次差分，零差异**；Wiki 的 `(1,4,6,6)` 展开式与英文站 `(0,2,2)/(0,2,3)/(0,2,4)` 三例（+1 换算后）全部复现。
- **不符合集中在接口契约层**：`fs(n, s)` 返回的是定义的第 **n+1** 项（多一个 B 块），不是第 n 项；`fsLimit(0)` 返回不在极限基本列中的表达式；不校验合法式；零/后继表达式未短路；`pred("0")` 违反 ONP2 协议。
- 与前两轮已审的 **0-Y、BMS 完全同构**：都是「复原 exe 的输出口径」与「Wiki 定义口径」之间差一块（或差 `l-1` 项）的系统性偏移，不是本文件独有的 bug。源码注释明确写出「原 VB 程序在此越界抛异常，这里返回原序列兜底」，属于 exe 复原取向。

## 2. 逐条审查

### 2.1 合法式与定义域（⚠️ 部分）

定义要求「1 开头的自然数序列」[citation:26]，并给出反例 `3,1,8,4`（首项不为 1）、`1,2,3,😰`（非自然数）。实现不校验，`parse()` 用 `Number.parseInt` 且把解析失败记 0：

| 输入 | `typeOf` | `pred` | `fs(1)` | 实测现象 |
|---|---|---|---|---|
| `"2,3"` / `"3,1,8,4"` | `3` | `"2"` / `"3,1,8"` | `"2,2"` / `"3,1,8,8"` | 首项非 1 仍被当合法式 |
| `"abc"` | `3` | `"a"` | `"0"` | 解析成 `[0]`，`render` 输出 `"0"` |
| `"1,-1"` | `3` | `"1,"` | `"1,-1"` | 负数参与阶差计算 |
| `"1,2,"` | `3` | `"1,"` | `"1,2,0"` | 尾部空段被解析成 0 |
| `""` | `3` | `""` | `"0"` | 空串被判极限（应为零表达式） |

### 2.2 三分类与前驱（✅ 合法式内符合）

`typeOf` 与定义对应；`pred` 对合法后继表达式（末项为一位的 `1`）正确：`"1"→"0"`、`"1,1"→"1"`、`"1,1,1"→"1,1"`。

- `pred("0")` 返回 `""`，**违反 ONP2「结果为 0 一律返回字符串 `"0"`」**。
- `pred` 用固定长度 `a.length-2` 截断，遇到两位数末项会截错：`pred("1,10") = "1,"`。不过 `pred` 只在后继表达式上有意义，而合法后继的末项恒为一位 `1`，所以标准式内不触发；这是协议误用路径的脆弱性。

### 2.3 坏根、阶差、展开（✅ 符合，差分验证）

按 Wiki 公式独立实现的参考器：

```
S[t] = G + B₀ + B₁ + … + B_{t−1}
B_m = B + m·d,  d = s_n − s_k − 1
k   = max{ j < n : s_j < s_n }
```

与实现 `fs(n, s)` 逐项差分：

```
样本数: 90 × 6 个 n
实现 == S[n+1] 的次数: 540
不一致: 0
```

样本含 Wiki 实例、英文站三例、以及 80 个随机生成的 1 开头序列（长度 2–10、值 1–15）。**展开出来的无限序列完全正确**，Wiki 实例 `(1,4,6,6)` 的展开式 `(1,4,6,5,7,6,8,7,9,…)` 与实现 `fs(n)` 前缀逐项一致 [citation:10]；英文站 `(0,2,2)/(0,2,3)/(0,2,4)` 三例整体 +1 换算后同样一致 [citation:2][citation:27]。洛谷第九章给出的 `(1,2)`, `(1,2,3)`, `(1,3,3)` 展开行也吻合 [citation:11]。

关于英文站「若 `a_k=0` 或 `a_k` 的父项等于 `a_k−1`，则套用 PrSS 规则」的显式分支 [citation:2][citation:17]：实现没有这个分支，但此时 `d=0`、`B_m ≡ B`，展开自动退化为 PrSS；Wiki 自己也说明「PrSS 可以看作 LPrSS 在 1,3 之下的特殊情况」[citation:10]。因此属于**等价实现**，不算偏差。

### 2.4 基本列第 n 项（❌ 主要偏差）

`expandArr` 的 `r` 长度为 `b.length + L·n − 1`。设 `|G| = i`、`|B| = L`、`n_orig = |S| = i + L + 1`，则

- 实现 `|fs(n)| = i + L·(n+1)`
- 定义 `|S[t]| = i + L·t` [citation:10][citation:12]

即 **`fs(n) = S[n+1]`**。以 `(1,4,6,6)` 为例（`|G|=1`, `L=2`）：

| n | 实现 `fs(n)` | 长度 | 定义 `S[n]` 长度 | 差 |
|---|---|---|---|---|
| 0 | `1,4,6` | 3 | 1 | +2 |
| 1 | `1,4,6,5,7` | 5 | 3 | +2 |
| 2 | `1,4,6,5,7,6,8` | 7 | 5 | +2 |
| 3 | `1,4,6,5,7,6,8,7,9` | 9 | 7 | +2 |

这个 +2 不是「多一项」而是「多一整块 B」，与 0-Y 的 `+ (l−1)`、BMS 的 `+1 块` 是同一件事的不同表现。PrSS 词条的 `S[m]=(G,B^m)` 与入门页 `(0)(1)(2)(2)[3] = (0)(1)(2)(1)(2)(1)(2)`（3 块）都采用 n 块口径 [citation:12][citation:16][citation:22]，而实现 `fs(3)` 给 4 块。

**结论：以 Wiki 定义为准，`fs(n)` 返回的不是定义规定的那个表达式；它是下一项。** 实测 `less(fs(n), fs(n+1))` 全程为真、`less(fs(2), s)` 为真，宿主若用它做标准式集合或比较，序数体系会整体偏移一格。

### 2.5 极限基本列与 `fsLimit`（⚠️ 部分）

定义极限基本列为 `(1,2),(1,3),(1,4),(1,5),…` [citation:26][citation:6]。实现 `fsLimit(a) = "1," + (a+1)`：

| a | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 实现 | `1,1` | `1,2` | `1,3` | `1,4` | `1,5` |

若协议基本列索引起自 1，`a≥1` 与定义第 a 项一致；`a=0` 返回 `1,1` 是**后继表达式**（`typeOf=2`），不在极限基本列中。若按 0-based 理解，则整体偏移一项。这一形态与 0-Y、BMS、KP Hydra、PSS Hydra 完全一致，是全库统一的 1-based / exe 口径问题。

### 2.6 零 / 后继的 `fs` 与比较（⚠️ / ❔）

- `expandArr` 对空序列、以及「末元素已是最小值」（找不到坏根）返回原序列兜底（源码注释说明原 VB 程序在此越界抛异常）。实测 `fs(1,"0")="0"`、`fs(1,"1")="1"`、`fs(1,"1,1")="1,1"`。定义中零/后继没有基本列，这条路径本不该被调用；实现未短路，但至少返回合法表达式，比 KP Hydra / PSS Hydra 输出非法串要好。
- `less`：定义未给出序数比较算法。实现为数组字典序。实测在 13 个标准式样本上满足反自反、非对称、完全性、传递性（0 违反），且与序列字典序一致。判定为**内部自洽、定义未覆盖**。

### 2.7 VB 兼容层（⚠️ 工程约束）

`vmid()` 精确模拟 VB 1-based `Strings.Mid`，三个 VB 系记号共用 [citation:21]；`vasc()` 用字符码 `> 45` 判「是否数字」，即 `'-'` 之后一律当数字，负号、小数点等会被误读。这些都是定义外的工程约束，在合法标准式上未造成偏差。

## 4. 整改建议（按优先级）

1. **先定基准**：明确本插件对齐「Wiki 定义」还是「复原 exe 协议」。当前实测与注释都指向后者。若继续保留 exe 行为，必须在接口文档写明「`fs(n)` 为定义第 n+1 项、`fsLimit` 采用 1-based」，否则使用者会按 Wiki 口径误用。
2. **若以定义为准**：把 `expandArr` 的块数改为 n，并用 `(1,4,6,6)`、`(1,3,3)`、PrSS `[3]` 例子做回归 [citation:10][citation:16]。
3. **加输入校验**（L-D3、L-D4、L-D5、L-D7）：改成「先解析、后判定」，去掉按字符数截断的写法。
4. **补 `fs` 类型短路**（L-D6）。
5. **把 90 样本差分脚本固化为回归测试**，尤其是 540 次零差异这条基线。
