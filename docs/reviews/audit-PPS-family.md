## 结论速览

**总判定：不完全遵守。**

- **骨架是忠实的**：坏根定位（第 X 项）、`L = y − X`、弱展开判定、PPS1 强展开 −1、PPS4 强展开的「在 (b, x) 内取最右 ≤ b 项的列标」、递推 `值 ≥ x 则 +L`，以及**基本列 `[n]` 截断到第 `y+nL−1` 项**，都与定义逐条对应。Wiki 页面给出的 4 个长表达式（含「地府第一层」「良序极限基本列」）在 `pps2` 上 `n=0..3` **逐项完全一致** [citation:4]。
- **但有三处会改变展开结果的实质偏差**：复制阶段多了一个定义里没有的「提升点」例外；PPS1 在 `b = x` 边界漏掉强展开的 −1；PPS4 在「找不到可回落项」时缺少「等同弱展开」兜底。按定义独立实现做差分，排除解析干扰后 `pps2` 有 197/1200 次不一致、`pps4` 有 554/1200 次不一致，全部可归到这三处（见 §2.1、§2.2 的根因分类表）。
- **PPM 侧问题更偏「定义覆盖不全」**：`ppm.ts` 自报名字是 **PPM 2**，实现的却是 **PPM 1.2** 的弱/强判定；PPM 2 独有的「判断序列字典序比较」与「`i > y−L+1`」在三个 PPM 文件里**完全没有实现**。`ppm3.ts` 的额外抬升经构造矩阵验证确实对应 PPM 3；`ppm00t.ts` 在 Wiki 无定义。
- **一个值得单独指出的好消息**：本家族的 `fs(n)` **与定义的基本列第 n 项一致**（`ppsEx` 的哨兵落在 `nL+x−1`，PPM 的 `this.x = nL+x−1`），不像前两轮审过的 0-Y / BMS / LPrSS / KP Hydra / PSS Hydra 那样整体返回 `S[n+1]`。前几份报告里「全库统一偏移一格」的说法要收窄到那五个记号。
- 另有两处工程缺陷：`bias=1` 解析步进在值 `9 / 99 / …` 上读错后续元素（**2026-11-07 归因已修订**：根因是 TS 统一框架把 `bias` 加进 `stored` 代入步进公式，C++ 原版用解析原值、9/99 均正确；仅影响 `bias=1` 记号，见文末「修订记录」）；8 个序列插件把零表达式 `"0"` 误判为后继（`typeOf=2`）。

## 范围与对应关系

Wiki「PPS」词条给出 **5 个定义**：PPS1（主定义）、PPM 1.2、PPM 2、PPM 3、PPS 4 [citation:4][citation:9][citation:5]。源码有 **11 个**插件，对应如下：

| 源码插件（id） | 自报 `name` | Wiki 对应 | 可判定性 |
|---|---|---|---|
| `pps2` | Parented Predecessor Sequence 2 | **规则逐条对应 PPS1 主定义**；但 Wiki 明确写「PPS2 和 PPS3 … 不在此给出定义」[citation:4] | 以 PPS1 为基准审查（见下注） |
| `pps4` | Parented Predecessor Sequence 4 | **PPS 4** ✓ [citation:5] | 有权威定义 |
| `ppm` | Parented Predecessor Matrix **2** | 实际实现 **PPM 1.2** 判定；名字错配 | 有定义，但名称与规则不符 |
| `ppm3` | Parented Predecessor Matrix 3 | **PPM 3** 的额外抬升 ✓ | 有定义 |
| `ppm00t` | Parented Predecessor Matrix 00T | 无（词条未列 00T） | 无定义 |
| `pps3` | PPS3 | 无（Wiki 不给定义） | 无定义 |
| `pps4_weak` / `pps4_second` / `pps4_third` / `pps4_extremely_weak` | weak / second extremely weak / third weak / extremely weak PPS4 | 无（词条只提到 phyrion「连夜修改了 10+ 个版本」[citation:4]） | 无定义 |
| `prss_parented` | Parented Primitive Sequence System | 无 | 无定义，且与 PPS1 骨架差异明显 |

> **关于 PPS1 的归属**：源码里没有名为 `pps1` 的文件。Wiki 说 PPS2/3 是「未能修改 PPS1 不足之处」的改版且不给定义 [citation:4]；但 `pps2.ts` 用的 `ppsEx(DEC_MINUS1, liftMode=false)` 恰好逐条实现「弱展开换 b / 强展开 −1 / 递推 +L」，因此本报告把 `pps2` 作为 **PPS1 主定义的对照对象**。这不等于认定 exe 编号与 Wiki 编号一一对应——命名歧义本身列为 P-D12。

## 1. 定义与实现的映射

### 1.1 内部表示（`core/seq.ts`）

- PPS 序列系 `bias = 1`：内部存储值 = 真实值 + 1，`0` 让给结束哨兵；`parse = txar(s, 1)`、`out = arout(a, −1)`。
- `ppsEx(a, n, x, decMode, liftMode)` 是 7 个序列插件共用的骨架（注释：「七份 exe 的 `Ex()` 骨架完全相同，只有两处不同」）：

| 定义概念 | 代码 |
|---|---|
| 末项值 `x`（Wiki 记作 x，代码里是真实值 `v−1`） | `const v = g(x-1)`（存储值） |
| 坏根 = 第 x 项（1-based） | `p = v − 2`，即 0-based 下标 `x−1` ✓ |
| `L = y − x` | `L = x_len − 1 − p` ✓ |
| 弱展开：末项与坏根之间含值 = b | `for i=x-2..p+1: if g(i)===g(p) a[x-1]=g(p)` ✓ |
| 强展开（PPS1）：末项 −1 | `DEC_MINUS1: a[x-1] -= 1` |
| 强展开（PPS4）：(b,x) 内最右 `≤ b` 项的**列标** | `DEC_SCAN_LE`：`c` 从 `X−2` 递减到 `b`，命中 `g(c)<=g(p)` 则 `a[x-1]=c+2`（真实值 = `c+1` = 列标）✓ |
| 递推 `值 ≥ x 则 +L` | `else if (v-1 < g(i-L)) a[i] = g(i-L)+L` ✓（`v−1 = x`） |
| `[n]` 截断到第 `y+nL−1` 项 | `a[n*L + x_len − 1] = 0` ✓ |

### 1.2 PPM 内部表示

`MatrixNotation` 采用**转置命名**：`x` = 括号个数 = Wiki 的列数，`y` = 括号内元素个数 = Wiki 的行数。`ppm.ex()` 里 `c0 = nc−1` 是末列非零行数 −1（LNZ 行序号），`pr = at(x−1,c0) − 1` 是坏根列标 −1，`L = x−1−pr` = 末列列标 − 末项值 [citation:9]。`descendOrFall()` 沿倒数第二列的父链判定弱/强，`copyRow()` 做「其他项展开」。

## 2. 逐条审查

### 2.1 PPS1 主定义（以 `pps2` 对照）

**符合项**：Wiki 四个长表达式逐项一致，是最有力的证据 [citation:4]：

| 输入 | n=1 的实现输出 / 参考器 |
|---|---|
| `0,1,0,3` | `0,1,0,2` / `[0,1,0,2]` ✓ |
| `0,1,0,2,0,4,4,3,0,4,3,0,11,9`（地府第一层） | `…,0,4,3,0,16` / 同 ✓ |
| `0,1,0,2,0,4,4,3,0,4,3,0,11,10` | `…,9,3,0,15` / 同 ✓ |
| `0,1,0,2,0,4,4,3,0,4,3,0,11,10,0,0,10,0,17,10` | `…,9,3,0,21,20,0,0,20,0,27` / 同 ✓ |

**差分（200 样本 × 6 个 n，值域 0..8 以排除解析干扰）**：一致 1003、不一致 197。根因分类：

| 根因 | 次数 | 例子 |
|---|---|---|
| 复制阶段「提升点」照抄 | 132 | `0,7,5,6,4,6,8,1,8,4` n=2：`got[15]=6`，参考器 `12` |
| 强展开漏判（`b = x`） | 65 | `0,3,1,0,5,1,7,6,1,4,2,5` n=1：末项 `got=5`，参考器 `4` |

**偏差一：定义里没有的「提升点」例外。** `ppsEx` 步骤 3 有 `if ((i - p) % L === 0)` 分支：每段起点强制 `a[i+L] = g(i)`（`liftMode=false`）照抄，而定义规则 4 只按「第 i 项值 ≥ x」决定 `+L` [citation:4]。当降级后的段起点值仍 ≥ x 时（典型：**弱展开且 `b ≥ x`**，或 `b = x` 未降级），定义要求抬 `L`，实现照抄。例：`0,7,5,6,4,6,8,1,8,4`（x=4, b=6, L=6）在 n≥2 时块首第 16 项实现给 `6`、定义给 `12`。

**偏差二：强展开在 `b = x` 时漏掉 −1。** 步骤 2 的守卫写成 `if (g(x-1) !== g(p))`：当坏根值 `b` 恰等于末项值 `x` 且中间没有同值项时，步骤 1 没改末项，但 `g(x−1)` 与 `g(p)` 相等，于是跳过 −1。定义规则 3 明确「否则将末项的值减 1」[citation:4]。

> `pps3`（`liftMode=true`）在提升点会再抬一档，与 PPS1 定义的差距更大（§1 的 1200 次对照里 525 次不一致），但 Wiki 不给 PPS3 定义，故只判「无权威定义可对照」。

### 2.2 PPS 4（`pps4` 及 4 个弱化版）

Wiki PPS 4：弱展开换 `b`；强展开「在第 b 列和第 x 列（都不含）之间找到最右侧的值 ≤ b 的项，将末项的值换为这个项的列标；**如果找不到，则等同弱展开**」；其他项展开 `i > y−L`；`[n]` 截断 `y+nL−1` [citation:5][citation:9]。

**符合项**：弱展开判定、强展开的扫描范围（源码 0-based `c` 从 `X−2` 到 `b`，对应 1-based 列标 `X−1 … b+1`，正是 `(b, x)`）、命中后取列标 `c+1`、递推与 `[n]` 截断，全部对应。`pps4` 与参考器在 646/1200 次完全一致。

**差分根因分类（554 次不一致）**：

| 根因 | 次数 | 例子 |
|---|---|---|
| 强展开扫描循环不进入 → 缺「等同弱展开」兜底 | 370 | `0,1,1,6,4,4` n=1：末项 `got=4`，参考器 `6` |
| 复制阶段「提升点」照抄 | 132 | 同 §2.1 |
| 提升点的另一触发（`b = x` 未降级） | 52 | `0,3,1,0,5,1,7,6,1,4,2,5` n=2：`got[18]=5`，参考器 `12` |

**偏差三（PPS4 专有）**：源码扫描循环 `for (c = g(x-1)-3; g(p)-1 <= c; c--)`，其兜底 `if (c === g(p)-1) a[x-1] = g(p)` 只在**循环至少进入一次**时才生效。当 `b > x−2`（即 `b ≥ x−1`）时循环条件初始即为假，源码既不扫描也不回落，末项保持原值。定义要求「找不到则等同弱展开」（末项 = b）[citation:5]。专项验证：

```
0,1,1,6,4,4   x=4 b=6  循环条件(b<=x-2)=false  pps4.fs(1)="0,1,1,6,4,4,6"  ref=[0,1,1,6,4,6,6]
0,1,1,7,4,4   x=4 b=7  同上                    pps4.fs(1)="0,1,1,7,4,4,6"  ref=[0,1,1,7,4,7,6]
```

**4 个弱化版**：`pps4_weak` / `pps4_extremely_weak` 与 `pps4` 在 480 次比较中仅 15 次不同；`pps4_second` / `pps4_third` 为 173 次。差异来自 `DecMode`（`<=` 收紧为 `==`、遇更小值跳到边界）与 `liftMode`。Wiki 未给这些版本的定义，只能判定「彼此不同、内部自洽」，**不能判定是否遵守定义**（P-D12）。

### 2.3 PPM 1.2 / 2 / 3（`ppm` / `ppm3` / `ppm00t`）

Wiki 三个矩阵版共用 LNZ / 坏根 / `L = y−x` / `[n]` 截断，差别在**末列展开的判定**与**复制阶段** [citation:9]：

| 版本 | 末列展开判定 | 其他项展开 |
|---|---|---|
| PPM 1.2 | 判断序列中末项与坏根之间存在值 = b → 弱，否则强 | `i > y−L` |
| **PPM 2** | 存在值 = b 时**比较「以该项为首的判断序列」与「以坏根为首的判断序列」的字典序**：前者大（或坏根不在末项祖先链上且该项存在）→ 弱；后者大或该项不存在 → 强 | **`i > y−L+1`** |
| PPM 3 | 同 PPM 1.2 | `i > y−L`，且**强展开时 LNZ 行元素每次复制增加一个复制单元长度** |

实测结论：

- `ppm.ts` 的 `descendOrFall()` 只做「沿倒数第二列父链是否存在与父同值」→ 这是 **PPM 1.2** 的判定；`copyRow()` 用 `pr < at(r-L,j)` 统一处理提升行/非提升行，没有任何字典序比较，也没有 `i > y−L+1` 的偏移。**PPM 2 的两处独有规则全部缺失**，但 `name` 却写死为 `'Parented Predecessor Matrix 2'`（P-D6、P-D7）。
- `ppm3.ts` 只覆盖 `copyRow()`：提升行在 `at(pr,c0) < at(x-1,c0)` 且 `j === c0` 时也 `+L`。构造矩阵 `(0,0)(1,1)(2,2)(3,3)(4,1)(5,5)` 实测触发：`ppm` n=2 给 `(6,4)`、`ppm3` 给 `(6,5)`，n=3 给 `(7,4)` / `(7,6)` ✓ 对应 PPM 3 的「强展开时 LNZ 行每次复制增加复制单元长度」。
- `ppm00t.ts` 改 `fsLimit` 为下三角矩阵（`a=2 → "(0)(0)(2)"`、`a=3 → "(0,0)(0,0)(2,0)(3,3)"`），与 Wiki 极限表达式 `(0)(1,1,1,1,1,...)` 不符；`ex()` 的尾部裁剪也是 exe 特性。Wiki 无 00T 定义。
- 三个 PPM 的 `pred("0")` 均返回空串 `""`（违反 ONP2「结果为 0 返回 `"0"`」）；`fsLimit(0) = "(0)(0)"`（`ppm`/`ppm3`）是两列全零，不在极限基本列中。
- `fs(n)` 的截断与定义一致：输入 `(0)(1,1,1)`（2 列）时 `fs(1)` 2 列、`fs(2)` 3 列、`fs(3)` 4 列，正是 `[n]` 展开到第 `y+nL−1` 列 [citation:9]。但 `ppm.ex()` 里有 `if (x===2 && y!==1) y--` 的行数收缩，输出表示会变（定义未规定此规范化）。

### 2.4 共性契约

| 检查 | 结果 |
|---|---|
| **零表达式** | 8 个序列插件 `typeOf("0") = 2`（应为 1），`typeOf("") = 1`。原因：`arout` 把空序列输出成 `"0"`，但 `txar("0", 1)` 把它读成单元素 `[0]`（存储值 1），`seqType0` 检查 `a[0]===0` 用的是存储值，永远不成立 |
| **解析步进缺陷** | `txar` 用 `i += trunc(log10(stored*100+1))` 推进，`stored = v + bias`。当 `v = 9 / 99 / …`（`v+1` 为 10 的幂）时步进多 1，后续元素被读错：`"0,9,11,1,1"` → 内部 `0,9,1,1,1`。Wiki 良序极限式含 `…,9,3,…` 正会触发 [citation:4]。**2026-11-07 修订：与 BMS 报告的两位数 `y` 推断错误不同源** —— 后者是 C++ `y=strlen(sr)/2+1` 的忠实移植；本处是 TS 把 7 份 exe 的 `txar` 合并为 `txar(s,bias)` 时，用 `stored=v+bias` 而非解析原值算步进所引入，C++ `txar` 用 `ap[i]`（原值）、9→2 / 99→3 均正确 |
| **`fsLimit`** | 序列系 `fsLimit(a) = "0,1,…,a"`；`fsLimit(0) = "0"`。若基本列 1-based（第 a 项 = `0,1,…,a`），`a=0` 越界；`pred("0")` 恰好返回 `"0"` ✓ |
| **零/后继的 `fs`** | 未短路：`pps4.fs(2,"0") = "0,0"`、`fs(1,"0,1,0") = "0,1,0,3,4"`（后继表达式被当极限展开） |
| **非法输入** | `"abc"` / `"-1,0,2"` / `"0,x,3"` 被静默接受并给出结果；无合法式校验 |
| **`less`** | 8 个序列插件在 13 个样本上：反自反 0 / 双向 0 / 不可比 0 / 传递违反 0，为严格全序；`less(fs(n),fs(n+1))` 全真。定义未给比较算法，只能判「内部自洽」 |
| **基本列 `[n]` 截断** | **与定义一致**（`nL+x−1`），这是本家族与前两轮五个记号最大的不同 |

## 3. 偏差与缺陷清单

| 编号 | 严重度 | 问题 | 证据 | 影响 | 建议 |
|---|---|---|---|---|---|
| P-D1 | **高** | 复制阶段「提升点」`(i-p)%L===0` 强制照抄，定义只按「值 ≥ x」决定 `+L` | §2.1/§2.2，132+52 次 | 弱展开且 `b≥x`（或 `b=x`）时块首值偏低，基本列项不是定义结果 | 删掉提升点例外，统一用 `g(i-L) >= x ? +L : 照抄`；`liftMode` 另作显式变体参数 |
| P-D2 | **高** | PPS1 强展开在 `b = x` 且中间无同值项时漏掉 −1 | 65 次；`0,3,1,0,5,1,7,6,1,4,2,5` | 末项未降级 | 守卫改为「步骤 1 是否真的执行过」的布尔标志，而非比较 `g(x-1) !== g(p)` |
| P-D3 | **高** | PPS4 扫描循环不进入（`b ≥ x−1`）时缺「找不到则等同弱展开」兜底 | 370 次；`0,1,1,6,4,4` | 末项保持原值，与定义「末项 = b」不符 | 把兜底提到循环外：循环未命中即 `a[x-1] = g(p)` |

## 4. 整改建议（按优先级）

1. **先修 P-D1 / P-D2 / P-D3**：这三处直接改变展开结果，且都能用本报告的分类脚本定位。改完后用 Wiki 四个长表达式 + 200 样本差分做回归，`pps2` 应达到 1200/1200、`pps4` 应达到 1200/1200（在排除解析缺陷的输入上）。
2. **修 P-D4 / P-D5**：解析与零表达式是输入层的正确性，且会影响 Wiki 良序极限式这类真实用例。P-D4 已确认只影响 `bias=1` 的记号（`bias=0` 的矩阵类与其他记号不受影响），改动限定在 `core/seq.ts` 的 `txar()` 即可。
3. **澄清 PPM 的版本归属（P-D6、P-D7）**：要么补齐 PPM 2 的字典序判定与 `i > y−L+1`，要么把 `name` 改成 PPM 1.2 并在文档写明；把 `ppm3` 的抬升规则与 Wiki PPM 3 逐字对照固化成用例。
4. **统一索引与协议（P-D8 ~ P-D11）**，与前几轮报告的建议一并处理。
5. **把「无定义插件」清单写进接口文档（P-D12）**：PPS2/3、4 个弱化版、`prss_parented`、`ppm00t` 只能保证「与复原 exe 一致」，不能宣称遵守 Wiki 定义。
