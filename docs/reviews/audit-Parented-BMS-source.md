## 结论速览

**对应关系确凿，展开算法逐行等价。5 条协议命令共 1049 次差分，零差异。**

| 命令 | C++ | TS | 比较次数 | 一致 |
|---|---|---|---|---|
| 1 | `limit()` | `fsLimit()` | 9 | 9 / 9 |
| 2 | `type0()` | `typeOf()` | 83 | 83 / 83 |
| 3 | `precursor()` | `pred()` | 83 | 83 / 83 |
| 4 | `expand()` → `Ex()` | `fs()` → `ex()` | **474** | **474 / 474** |
| 5 | `compare0()` | `less()` | 400 | 400 / 400 |

- **身份对上了**：C++ `name0()` 输出 `"Parented Bashicu Matrix"`（第 177 行），与 `parented_bms.ts` 的 `name` 逐字相同；而 `bashicu_matrix.ts` 的 `name` 是 `"Bashicu Matrix"`。更硬的证据是 `Ex()` 第 190 行 `r=a[x-1][t]-1` —— **父行号直接取自末行末列的值，不调用任何 `par()`**，正是 `parented_bms.ts` 注释「与 BMS 的差别：不用 par() 求父」所描述的特征。已找到 15 个反例证明它和 `bashicu_matrix.ts` 展开结果不同，两个插件不是同一份源码。
- **TS 不是机械翻译，是「修复式移植」**：C++ 里有 6 处未定义行为/原生缺陷（悬垂指针、野指针、0 值死循环、定长溢出等），TS 全部补成了可运行的等价逻辑。把 C++ 按「原意」修好之后，两者输出**完全一致**；差异只存在于「按 C++ 字面语义根本跑不起来」的路径上。
- **顺带把前两轮两个缺陷的锅归位了**：
  - BMS 报告里「第 2 行含两位数时列数推断错误」——**C++ 原生就有**：`y=strlen(sr)/2+1`（第 60 行），`"10,11,12"` 长 8 → y=5。TS 的 `(cellStr.length>>1)+1` 是忠实移植，不是自己写错。
  - PPS 报告里「`bias=1` 时 9/99 解析步进错位」——**TS 统一框架引入的**：C++ `txar` 用**解析出的原值** `ap[i]` 算步进（`log10(ap[i]*100+1)`），9 → 2 正确；TS 把 `stored = v + bias` 塞进了同一个公式，9 在 bias=1 时变成 10 → 步进 3，多走一格。这份 C++ 对应的 `parented_bms.ts` 是 `bias=0`，**不受影响**。

## 2. `Ex()` 逐行对照（核心）

| C++ | TS (`parented_bms.ts`) | 判定 |
|---|---|---|
| `for(i=0;i<x;i++) for(j=0;j<y;j++) ac[i][j]=a[i][j];` (187-188) | `:14-16` `const w = ...` 逐格备份 | ✅ **连这段从未被使用的死代码都原样搬了** |
| `for(t=0;a[x-1][t]!=0;t++); t-=1;` (189) | `:18-20` `while(at(x-1,c0)!==0) c0++; c0--` | ✅ `t` ↔ `c0`（末行最右非零列） |
| `r=a[x-1][t]-1;` (190) | `:22` `pr = at(x-1,c0)-1` | ✅ 父行号直接取元素值 |
| `l=x-1-r;` (191) | `:23` `L = this.x-1-pr` | ✅ |
| `if(x==2&&y!=1) y-=1;` (192) | `:25` | ✅ 位置也一致（在右侧补齐之前） |
| `for(j=t;j<y;j++) a[x-1][j]=a[r][j];` (193) | `:26` `for(j=c0;j<y;j++) put(...)` | ✅ **含 `j=t`**：末项本身回落为父行同列值，不是 −1 —— 这正是 "Parented" 的语义 |
| `for(i=x; i<x+n*l+1; i++)` (194) | `:28` `for(r=this.x; r<=n*L+this.x; r++)` | ✅ 上界含 `n*l` |
| `if((i-r)/l*l==i-r)` (196) | `:29` `(r-pr)%L===0` | ✅ 整数除法/取模，在 `i-r>0` 时等价 |
| 提升行 `j<t ? +l : 照抄` (196) | `:31-32` `j<c0 ? +L : 照抄` | ✅ |
| 其余行 `a[i-l][j]>=a[x-1][t] ? +l : 照抄` (197) | `:34-39` `< at(x-1,c0) ? 照抄 : +L` | ✅ 等价；**阈值都在第 193 行替换之后读取**，所以取的是 `a[r][t]`，两边一致 |
| `x=x+n*l-1;` (199) | `:42` `this.x = n*L+this.x-1` | ✅ 含「多写一行、输出时截掉」的 off-by-one |

## 3. 差异清单（全部是 C++ 未定义行为 → TS 护栏）

| # | C++ 问题 | 位置 | TS 处理 | 影响 |
|---|---|---|---|---|
| D1 | `txar` 步进用 `(int)log10(ap[i]*100+1)`，当 `ap[i]==0` 时步进 **0** → `j` 不变、无限循环并越界写 `ap[L]` | 第 33 行 | `seq.ts:40`：`stored>0 ? 原公式 : 2`，按「位数 + 1 个分隔符」补正 | **必需修复**。实测 `sr="0,1"` / `"0"` / `"0,0,1"` 在 C++ 字面语义下全部挂死；含 0 的行（如 `(0,0)(0,1)`）是常见合法输入 |
| D2 | `txar` 返回局部数组 `ap[L]` 的指针（悬垂） | 第 34-35 行 | 返回 `number[]` 值 | 消除 UB，读到的值一致 |
| D3 | `txma` 返回局部 `p[V]` 的指针（悬垂）；`o[V][L]` 也是局部 | 第 59-62 行 | 返回 `{m, rows, cols}` 对象，`m` 为新建数组 | 消除 UB |
| D4 | **`expand` 里 `int (*cc)[L]` 未初始化就直接写 `*(*(cc+i)+j)`**（野指针） | 第 109、117 行 | `fs()` 直接 `this.m = r.m`，无中间副本 | **最严重的一处 UB**。C++ 意图是「拷一份再改」，但 `n==0` 用 `c`、`n>0` 用 `cc`，两者不重叠，所以 TS 原地修改等价（474/474 差分证实） |
| D5 | `sr[40]` / `ap[L]` 定长；行长 ≥40 字符或元素 >20 个会溢出 | 第 38、27 行 | 无长度限制（JS 字符串 / 动态数组） | 长表达式行为不同，合法输入不触发 |
| D6 | `comp` 全等时 `i` 到 `V`，访问 `aa[V]` 越界读 | 第 75-79 行 | `comp(a,b,300)` + `matrixCompare` 里 `concat(pad(300))` 补 0 | 400/400 差分一致；极端长输入可能不同 |
| D7 | `y=strlen(sr)/2+1` 假定每个元素都是 1 位数 | 第 60 行 | `(cellStr.length>>1)+1` —— **忠实移植，同错** | 两位数行列数推断错误：`(0)(10,11,12)` 两边都算 y=5，展开后 `l<0`、`x<0`，输出空串。**这是 C++ 原生缺陷，不是 TS 偏差** |
| D8 | `compare0` 里 `x=0` 但全局 `y` 不清零 | 第 147 行 | 纯函数，每次 `txma` 独立返回 `cols` | 实测无影响（`y` 不参与 `comp`，compare0 也不输出矩阵） |

**结论**：D1–D6 是 TS 为让源码「能跑」而做的必要补正，D7 是原样保留的原生缺陷，D8 无影响。**在两者都能运行的输入域上，输出 100% 一致。**

## 4. 两个「同源」易混点的澄清

### 4.1 Parented BMS ≠ Bashicu Matrix（两个插件）

`bashicu_matrix.ts` 用 `bmsPar()` 求父行并算 `delta[j]` + `bmsAsmt()`；`parented_bms.ts` 直接取元素值当父行号、末行整体回落、按 `a[i-l][j]>=a[x-1][t]` 决定是否 `+L`。简单输入上两者巧合一致（`(0,0)(1,1)(2,2)` 的 `fs(1)` 都是 `(0,0)(1,1)(2,1)`），但已找到 **15 个反例**，例如：

```
(0,0)(1,1)(2,0)(3,1)  n=1
  parented : (0,0)(1,1)(2,0)(3,0)(4,4)(5,3)
  bashicu  : (0,0)(1,1)(2,0)(3,0)
(0)(1,1)(2,2)(3,1)     n=1
  parented : (0,0)(1,1)(2,2)(3,0)(4,4)(5,5)
  bashicu  : (0,0)(1,1)(2,2)(3,0)(4,1)(5,2)
```

**你给的这份 C++ 对应的是 `parented_bms`，不是 `bashicu_matrix`** —— `name0()` 与 `Ex()` 两处特征都已确认。

### 4.2 `bias` 是 TS 统一框架引入的，不是 C++ 原意

C++ `txar` 的步进变量是**解析出的原值** `ap[i]`，因此 `9 → log10(901)=2`（正确）、`99 → 3`（正确）。TS 把 7 份 exe 的 `txar` 合并成 `txar(s, bias)`，让 `stored = v + (bias?1:0)` 参与步进：

```
v=9   C++步进=2  TS(bias=0)=2  TS(bias=1)=3  ← 偏离
v=99  C++步进=3  TS(bias=0)=3  TS(bias=1)=4  ← 偏离
TS txar("9,3", bias=1) → [10,0,0,...]（第二个数被吃掉了）
```

这解释了《PPS 家族实现审查报告》里的 P-D4：那个 9/99 缺陷**只影响 `bias=1` 的 8 个 PPS 系插件**，`parented_bms`（`bias=0`）和这份 C++ 都不受影响。是统一框架合并时引入的行为变化，不是复原自原 exe 的缺陷。
