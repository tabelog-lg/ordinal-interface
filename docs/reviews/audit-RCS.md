## 结论速览

**总判定：非 fallback 分支完全符合坏根定位；整体「无法完全判定」——定义只给了坏根规则，没给展开规则，且两处措辞自身有歧义。**

- **非 fallback 部分很干净**：按「祖先链中最靠右覆盖全部模 k 余数类者」定位坏根、再按 LPrSS 式展开（末项 −1、复制单元逐项加 `末项−坏根−1`），与实现 **560/560 次差分零差异**。定义里「对任何自然数 n，存在一项模 k 同余 n」等价于覆盖全部 k 个余数类，源码的 `intd()` 全 1 判定逐条对应。
- **但 490/1050 次样本走的是 fallback 分支**（祖先链上没有任何 x 覆盖全部余数类，占比很高），这一支在定义里只给了「坏根为第 0 项 s」，**没有给展开规则**；源码用的是 exe 的「虚拟第 0 项 + 复制单元长 x + 增量 `末项−r_stat−1`」。定量对照显示两者不等价：`1,3,6,9,12`（k=3）定义 s=2、源码隐含 r_stat=−1，复制增量 **12 vs 9（差 k=3）**；`1,4,7,10,13` 定义 s=0、源码 r_stat=−1，增量 **13 vs 12（差 1）**；只有 `1,3,5,7,9` 恰好一致（同 s=0）。
- **定义自身有两处不闭合**：`[0,-k)` 在 k>0（源码的 `delta = 末项−父项`）时按字面是空区间，s 不存在；「x 右边的项中（包括末项与 x）」可理解为**序列区间**（源码采用）或**祖先链上的项**（字面）。构造 `1,3,5,7,9,12,11`（k=2）时两读法给出不同坏根，源码实测采用前者。
- **接口层有一个比前几轮更刺眼的问题**：零表达式与非法串调用 `fs` 会产生**负数**（`fs(1,"0") = "-1"`、`fs(2,"0") = "-1,-3"`、`""`/`"abc"` 同样）；含 0 的序列被 `txar` 当哨兵截断（`1,0,2` → `pred="0"`）。`fsLimit(0)="1,1"` 是后继表达式、越界。
- **好消息**：`bias=0`，**不受 PPS 家族那个 9/99 解析步进缺陷影响**；`typeOf("0")=1`、`pred("0")="0"` 正确；`less` 序性质（反自反/非对称/完全/传递）全 0 违反；纯函数性通过。

| # | 定义条款 | 判定 | 说明 |
|---|---|---|---|
| 1 | 极限表达式 `1,ω` | ⚠️ | `fsLimit(a) = "1,"+(a+1)` 与基本列相容（a≥1），但 `fsLimit(0)="1,1"` 是后继、越界 |
| 2 | `k` = 末项与其父项的差 | ✅ | `delta = g(x-1) - g(fb[x-1])`，父项 = 左侧最右小于末项者 |

| 4 | fallback：坏根为第 0 项 s，`s∈[0,-k)` 最小缺失余数 | ❌ / ❔ | 定义区间记号不闭合；源码 `r_stat` 从余数 1 起算，与定义 s 在多数例上不等价；展开规则缺失 |

| 父项 | `residue_class.ts:30-39` | `fb[i]` = 最右 `j<i` 使 `g(j)<g(i)`；`g(i)===1 → fb[i]=-1`，`fb[0]=-1` |
| `k`（末项 − 父项） | `:41` | `delta = g(x-1) - g(fb[x-1])` |

| fallback 的 s | `:52-61` | `r = 1-delta` 起，沿父链找第一个**数值** `r+delta` 缺失的余数；`k===-1` 时 `r = 末项 − r_stat` |
| 末项 −1 | `:64` | `a[x-1] = g(x-1) - 1` |

| 极限基本列 | `:23-25` | `seqLimitTwo(a)` → `"1,"+(a+1)` |
| 类型 / 前驱 / 比较 | `core/notation.ts` `SeqNotation` | `seqType0` / `txar + 去末项` / `seqCompare` |

## 2. 逐条审查

### 2.1 非 fallback：坏根定位与展开（✅ 560/560）

按定义复算「祖先链从右往左第一个使 `[x..末项]` 覆盖全部 k 个余数类者」，实测与源码输出一致。代表性实例：

| 输入 | k | 最靠右覆盖者 | `fs(1)` | 参考器 |
|---|---|---|---|---|
| `1,2,3,4,5` | 1 | 下标 3（值 4） | `1,2,3,4,4` | 同 ✓ |
| `1,2,4,6,8` | 2 | 下标 0（值 1） | `1,2,4,6,7,8,10,12` | 同 ✓ |
| `1,2,3,5,7,9` | 2 | 下标 1（值 2） | `1,2,3,5,7,8,9,11,13` | 同 ✓ |
| `1,2,6,7,8,9,10` | 1 | 下标 5（值 9） | `1,2,6,7,8,9,9` | 同 ✓ |

「对任何自然数 n，存在一项模 k 同余 n」→ 因模 k 只有 k 个余数类，等价于覆盖 `{0,…,k−1}`，源码 `intd` 逐类检查 ✓。

### 2.2 定义歧义一：「x 右边的项」是序列区间还是祖先链（⚠️）

源码用 `a.slice(k)`，即**序列中从 x 到末项的所有项**（含非祖先项）。若按字面读作「祖先链上 x 右边的项（含末项与 x）」，会给出不同坏根。构造：

```
1,3,5,7,9,12,11   k=2   父=9   祖先链值=[9,7,5,3,1]（全奇数，余数只有 1）
  序列 [1..末项] 含 12（偶数）→ 余数 {0,1} 覆盖 → 源码坏根=下标 4（值 9）
  祖先链上项 {9,7,5,3,1,11} → 余数只有 1，不覆盖 → 应走 fallback
  实测 fs(1) = "1,3,5,7,9,12,10,13"（非 fallback）
```

源码明确采用「序列区间」读法。这与定义措辞不冲突（「包括末项与 x」更像区间描述），但需在文档中固化，否则同一定义可推出两套结果。

### 2.3 定义歧义二：`[0,-k)` 与 k 的符号（⚠️）

源码 `k = 末项 − 父项 > 0`。按字面 `[0,-k)` 是**空区间**，s 无定义；只有当 k 取「父项 − 末项」（负数）时 `-k>0`，区间才是 `[0,k)`。定义自身的记号未闭合。本报告按最自然的解读 `s ∈ [0,k)`、s 为祖先链余数集中最小缺失者来对照，并明确这只是**一种解读**。

### 2.4 fallback 分支（❌ 与定义外推不等价 / ❔ 展开规则缺失）

490/1050 次样本触发 fallback。源码在 `k===-1` 时：

```
r_stat = 从数值 1 起、沿父链找第一个「r+delta」不出现的余数；
增量 = (末项 − r_stat) − 1；复制单元长 l = x（虚拟坏根在第 0 项之前）。
```

按定义 `s` 外推的 LPrSS 增量应为 `末项 − s − 1`。定量对照：

| 输入 | k | 祖先余数 | 定义 s | 源码 r_stat | 源码增量 | 定义增量 | 差 |
|---|---|---|---|---|---|---|---|
| `1,3,5,7,9` | 2 | {1} | 0 | 0 | 8 | 8 | 0 ✓ |
| `1,3,6,9,12` | 3 | {0,1} | **2** | **−1** | **12** | **9** | **+3 (=k)** |
| `1,4,7,10,13` | 3 | {1} | **0** | **−1** | **13** | **12** | **+1** |
| `1,2,3,5,7,9` | 2 | {0,1} | 无缺失（非 fallback） | 0 | 8 | 8 | — |

源码 `r_stat` 从余数 **1** 开始检查（跳过 0），且检查的是数值 `r+delta` 而非模值，因此当最小缺失余数 ≥1 时会得到负值，增量比定义外推多出约 k。**这一支不能判定为「违反定义」**（定义没给展开规则），但可以确定：**它不等价于按定义 s 外推的 LPrSS 展开**，是 exe 语义。报告把这一支列为「定义未覆盖 + 待澄清」。

### 2.5 接口契约（⚠️）

| 检查 | 结果 |
|---|---|
| `fsLimit` | `a=0 → "1,1"`（type=2 后继，越界）；`a≥1 → "1,a+1"`（极限）✓ |
| `typeOf("0")` / `pred("0")` | `1` / `"0"` ✓（`bias=0`，没有 PPS 系零表达式误判） |
| **零/非法输入的 `fs`** | `fs(1,"0") = "-1"`、`fs(2,"0") = "-1,-3"`；`""` 与 `"abc"` 同样；`fs(1,"1,-1,2") = "1,-2"`。**产生负数**，比「静默接受」更严重 |
| 含 0 的合法式 | `1,0,2` → `type=2`、`pred="0"`、`fs(1)="0"`：`txar` 把 0 当结束哨兵，序列在第一个 0 处截断。若定义中的「自然数」含 0，合法式会被破坏 |
| 零/后继的 `fs` | 未短路：`fs(1,"1")="0"`、`fs(1,"1,1")="1"`（输出仍是合法串，但语义路径不对） |
| 非法输入 | `abc` / `-1` / 首项非 1（`2,3` → `fs(1)="2,2"`）都被接受；无合法式校验 |
| 解析步进 | `bias=0` 时 `txar` 步进恒为「数字位数 + 1」，**9/99/多位数均正确**，不受 PPS 家族的解析缺陷影响 ✓ |
| `less` | 字典序；13 样本上反自反 0 / 双向 0 / 不可比 0 / 传递违反 0，为严格全序；`less(fs(n),fs(n+1))` 全真。定义未给比较算法 |
| 纯函数性 | `fs` 两次一致 ✓、`less` 后 `fs` 一致 ✓、`fs` 后 `less` 一致 ✓ |
| 死循环 | **无**：`0,2,4`、`2,4,8`、`""`、`abc` 等全部正常返回（对比 CpS 与 LELS 会挂死） |

## 4. 整改建议（按优先级）

1. **补定义（R-D4、R-D1、R-D2）**：把展开规则、`[0,-k)` 的记号、「x 右边」的读法写进接口文档；这是判定 RCS 是否合规的前提，否则只能给出「坏根定位符合、展开不可判定」的结论。
2. **修 R-D5 / R-D6**：`fs` 按 `typeOf` 分流、对 `delta<=0` 与非法串直接返回；解析层去掉 0 哨兵歧义。这两项不需要动定义即可修，且能立刻消除负数输出。
3. **对齐 fallback（R-D3）**：待定义补全后，用 `1,3,5,7,9`、`1,3,6,9,12`、`1,4,7,10,13` 三个用例固化回归；若目标是复刻 exe，则在文档注明「fallback 按 exe 实测，与定义外推不等价」。
4. **统一索引与协议（R-D7、R-D8）**，与前几轮报告的建议一并处理。
